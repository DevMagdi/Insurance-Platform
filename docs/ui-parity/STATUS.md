## State labels

`غير موجودة` = no screen/route; `قديمة` = prior UI not brought forward; `مُعاد تنسيقها` = existing screen restyled but still short of the reference; `مبنية` = implementation exists but visual proof is pending; `مطابقة بلقطة` = only after an actual product screenshot and parity review. No screen in this matrix is marked `مطابقة بلقطة`.

## Tokens / fixed constraints

- Primary `#4F46E5`; sidebar `#0E1424` (232px expanded, 76px collapsed in the request workspace); background `#F3F4F9`; cards radius `18px`; font **IBM Plex Sans Arabic**.
- No schema/database changes. CRM changes preserve conversion/business rules and add a server-side client-list projection over `converted_corporate_client_id` + `assigned_to`; the seller list query filters to the current actor. Full corporate records continue to require `corporate.view`.
- Data-model limit: the FK from `CrmLead.converted_corporate_client_id` and mutable `assigned_to` connect the converted client to its currently assigned lead. The CRM activity log records assignment events, but there is no dedicated immutable owner-at-conversion field; if fixed ownership after later reassignment is required, propose and approve that relationship separately. No ownership column is added in this pass.
- No production screen should be populated from invented demo records. Any future QA capture with mocked network fixtures must be labeled as fixture-rendered, not production evidence.

## Security work in this pass

- CRM sales role (`crm.manage` without `crm.convert`) is self-scoped independently of broad company scope. This applies at the API boundary to lead list/detail/update/move/activity/convert/bulk operations, pipeline and stats/KPI, tasks, imports and sales-performance reporting.
- Import creation is assigned to the seller; import batches and row-error exports are limited to the uploader. Task counts join through the lead owner, not the task assignee.
- Stage counts are seller-scoped and stage-definition mutation is manager-only. Manager reassignment remains available and writes an assignment activity record.
- CRM and client-list access are covered by backend unit tests for seller-vs-other-owner denial, manager access/reassignment, list/Kanban self filters, stage count scope, stage-admin denial, and converted-client visibility. The client-folder endpoint gives CRM sellers only lead-derived contact data and returns 404 for another seller’s client. A new module-scoped PostgreSQL fixture/test seeds two sellers, a manager, and isolated leads, then exercises real-runtime seller A/B access, 404 denial, manager reassignment, and persisted activity/audit. Its first CI attempt failed before the assertions because FastAPI `Query` defaults were passed directly; explicit values are now supplied and a fresh database-backed run is pending. Manual authorization checks remain outstanding.
